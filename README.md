# ThreatStream — Real-Time Threat Intelligence Dashboard

ThreatStream is a real-time threat intelligence platform that ingests security events through **Apache Kafka**, processes them in a **Spring Boot** backend, and streams live updates to a **React** frontend with interactive data visualizations.

## Architecture Overview

```
Kafka Topics                  Spring Boot Backend              React Frontend
┌─────────────┐    consume    ┌──────────────────┐    REST     ┌──────────────┐
│threat-events │───────────→  │ Event Processing │───────────→ │  Dashboard   │
│alert-rules   │───────────→  │ Alert Management │  WebSocket  │  Event Feed  │
│system-metrics│───────────→  │ Metrics Agg.     │───────────→ │  Alerts      │
└─────────────┘               └──────────────────┘             └──────────────┘
```

## Domain

ThreatStream monitors a network for security threats. Events are generated by simulated intrusion detection systems, firewalls, and SIEM tools. The platform:

- **Ingests** raw security events via Kafka topics
- **Processes** events, matching them against alert rules
- **Streams** live data to analyst dashboards via WebSocket/SSE
- **Visualizes** threat patterns with charts and maps
- **Enforces** role-based access (Viewer, Analyst, Admin)

## Kafka Topics

Three topics produce simulated data:

**threat-events** — Raw security events (1 every 2-5 seconds)
- Fields: id, sourceIp, destinationIp, type, severity, geo (country/lat/lon), description, timestamp
- Event types: INTRUSION_ATTEMPT, MALWARE, DDOS, BRUTE_FORCE, DATA_EXFIL, RECON
- Severities: LOW, MEDIUM, HIGH, CRITICAL
- ~10% of events have null geo data (legitimate edge case)

**alert-rules** — Rule match notifications (1 every 10-15 seconds)
- Fields: id, ruleId, ruleName, matchedEventId, action, severity, timestamp
- Actions: BLOCK_IP, QUARANTINE, NOTIFY, ESCALATE

**system-metrics** — System health data (1 every 5 seconds)
- Fields: eventsPerSecond, avgLatencyMs, activeConnections, cpuPercent, memoryPercent, kafkaLag, timestamp

## Tech Stack

**Backend**
- Java 21, Spring Boot 3.2
- Spring Kafka (embedded broker via spring-kafka-test)
- Spring WebSocket (STOMP + SockJS)
- H2 in-memory database
- JWT authentication
- Lombok

**Frontend**
- React 18, TypeScript, Vite
- Tailwind CSS v4
- Chart.js + react-chartjs-2
- Zustand (state management)
- Axios (HTTP client)

## User Roles

| Role | Permissions |
|------|-------------|
| VIEWER | View dashboard, events, alerts (read-only) |
| ANALYST | Above + acknowledge alerts, add notes to events |
| ADMIN | Above + manage alert rules, export data, manage users |

## Getting Started

**Backend:**
```bash
cd backend
mvn spring-boot:run
```
The embedded Kafka broker starts automatically. Backend runs on port 8080.

**Frontend:**
```bash
cd frontend
npm install
npm run dev
```
Frontend runs on port 3000 with API proxy to 8080.

**Demo Accounts** (password: `password123`):
- `viewer` — VIEWER role
- `analyst` — ANALYST role
- `admin` — ADMIN role

## API Endpoints

**Auth:**
- POST `/api/auth/login` — Login, returns JWT token
- POST `/api/auth/register` — Register new user

**Events:**
- GET `/api/events` — Paginated events (supports `?severity=`, `?type=`, `?from=`, `?to=`, `?page=`, `?size=`)
- GET `/api/events/{id}` — Single event with linked alerts
- POST `/api/events/{id}/notes` — Add note (ANALYST+)

**Alerts:**
- GET `/api/alerts` — Paginated alerts (supports `?severity=`, `?action=`)
- GET `/api/alerts/{id}` — Single alert
- POST `/api/alerts/{id}/acknowledge` — Acknowledge alert (ANALYST+)

**Dashboard:**
- GET `/api/dashboard/metrics` — System metrics + event aggregations

**Streaming:**
- WebSocket endpoint at `/ws` (STOMP over SockJS)
- Topics: `/topic/events`, `/topic/alerts`, `/topic/metrics`
